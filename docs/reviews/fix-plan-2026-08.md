## 2. Wrong inside a 🔴 (always-surface) category — verified factual errors in highest-severity rules

The correctness audit's P1 class. In each case the *rule* survives; the stated mechanism or example is wrong and an agent following the text verbatim repeats the error.

**2.1 — §B12 (🔴) has the `jsonwebtoken` `aud` direction inverted: a token carrying a foreign audience is *rejected* by default, not accepted.** *[COR #1]*
- Where: `security.md:38` ("`jsonwebtoken` checks `aud` *only if the token contains one*, so a token minted by the same IdP key for a **different service or tenant** authenticates"), `references/sources.md:176` (same reading recorded as grounding).
- Evidence (compiled, jwt 9.3.1 and 11.0.0, default `Validation::new(HS256)`): token WITH `aud=other-service` → `REJECTED: InvalidAudience`; token WITHOUT `aud` → `ACCEPTED`; `iss` never checked unless `set_issuer`. The doc line the spec paraphrases means the opposite of what the spec concludes. REQUIRED remedy (`set_audience`, `set_issuer`, `set_required_spec_claims(["exp","aud","iss"])`) is exactly right; a reviewer who tests the spec's stated scenario sees it rejected and concludes the rule is noise.
- Fix: replace the mechanism sentence with "a token that carries an `aud` the service did not configure is rejected, but a token that *omits* `aud` is accepted, and `iss` is not checked at all unless set — so an IdP-issued token for another tenant (same key, different `iss`, or no `aud`) authenticates". Update `sources.md:176` to quote the observed behavior, not the ambiguous doc line. Same pass as 1.3.

**2.2 — §A1 (🔴) names a real crate as a hallucination: `tokio-utils` exists; and the `rust-decimal` clause conflates two names.** *[COR #2 + COR #16 — same sentence]*
- Where: `deps-macros-ergonomics.md:45` ("`tokio-utils` does not exist, `tokio-util` does; … `rust-decimal` does not exist, `rust_decimal` does — and the typo'd variant has been weaponized").
- Evidence: crates.io API 2026-09-02: `tokio-utils` created 2023-03-31, 516,164 downloads, max 0.1.2 (benignness not assessed — irrelevant to the claim). crates.io normalizes `-`/`_`, so `rust-decimal` *cannot* be registered separately; the weaponized name was `rustdecimal` (no separator), now deleted. `:37` already names `rustdecimal` correctly. This is a 🔴 slopsquatting rule teaching the exact wrong reflex: an agent that "knows" `tokio-utils` does not exist will not verify it when it appears in a `Cargo.toml`.
- Fix: drop the "does not exist" list framing entirely — the rule is "verify every name against the registry, including `-`/`_` variants"; a hard-coded non-existence list rots. If an example is kept, date it. Rewrite the `rust-decimal` clause to name `rustdecimal` as the weaponized typo and state the normalization rule.

**2.3 — §B5 (🔴) lists `bool` as invalid for `mem::zeroed`, and describes the failure as silent when std aborts loudly; the `mem::uninitialized` contract is understated.** *[COR #3]*
- Where: `unsafe-and-ffi.md:20` (`mem::zeroed::<T>()` "… `bool`, `&T`, `&mut T`, `Box<T>`, `NonZero*` … the compiler will not stop the misuse"), `unsafe-and-ffi.md:19` (`mem::uninitialized` "instant UB for any type with invariants").
- Evidence (rustc 1.97.0, debug and `-O`): `zeroed::<bool>()` → `false`, exit 0 (zero *is* the valid value); `zeroed::<&u8>()`/`Box<u8>`/`enum {A=1,B=2}` → "attempted to zero-initialize type … which is invalid … non-unwinding panic. aborting." in both profiles (std's `assert_zero_valid`); `uninitialized::<bool>()` → `true`, `uninitialized::<u32>()` → `0x01010101` (0x01-fill mitigation). Docs: `uninitialized` is UB "on nearly all types, including integer types".
- Fix: remove `bool` from the `zeroed` list; state that std aborts at runtime with `attempted to zero-initialize type …` for the provable cases and that this is a best-effort mitigation, not a guarantee (BAN stays — the docs define it as UB); quote the `uninitialized` docs' "nearly all types, including integer types".

**3.3 — `JoinHandle::abort()` and `tokio::time::timeout` cannot stop a running `spawn_blocking` closure.** *[GAP 3]* 🟡; 🔴 when the work's duration is attacker-influenced (the §B14/§F3 escalation).

**3.5 — SSRF from a user-supplied URL; reqwest's default redirect policy bypasses the host check.** *[GAP 5]* 🟡 (matches §C2's other injection bullets; escalation would be a maintainer tier decision).
- Where: `security.md:87–92` (§C2 holds path / archive / command / SQL injection — no outbound-request bullet), `deps-macros-ergonomics.md:151` (§C12 URL row says "`@` in userinfo → SSRF (→ §C2)" — points at a §C2 bullet that does not exist; this resolves it).
