## Method and limits

Rounds 2–4 checked ids, versions, quotations, numbers and markup. Round 4 named what none of them had done: a read that compares rules with each other when the same thing is said in different words. This round is that read.

- **Full read for meaning.** Every shipped text was read in full, in order: `SKILL.md`, the 22 sphere files, `references/sources.md` (all 436 lines, including 336–425, which rounds 3 and 4 list as unread), the three commands, and the agent brief of `audit-project.workflow.js` (lines 260–316). For each rule the question was whether another rule, a trigger row, a file header, a command or a ledger entry says something different about the same construct.
- **Recomputation of worked examples.** The examples that carry numbers or a claimed outcome were recomputed by hand: the three-cycle and the `bool`/`u8` fixtures of the positional-format rule, the `dedup` result, the `Tag` round trip, the backoff waves (t+1, t+3, t+7), 22/40, 56/240 and 32/56.
- **Two outside checks.** The OWASP API Security Top 10 2023 list was fetched. The `tracing-attributes` source (`expand.rs` and `lib.rs`, branch `v0.1.x`) was fetched and read for the `ret` argument.
- **Not done.** Nothing was compiled or run. Facts about Rust 1.93–1.100 and the 2026 advisories were not checked again; rounds 2 and 3 did that. The JavaScript of the workflow was not re-read beyond the agent brief and a keyword scan. One reviewer read everything in one context, which is the mode `SKILL.md` advises against for a full pass: it finds cross-file disagreement well and is weaker on depth per sphere. Nothing in `skill/` or `commands/` was changed by this round.

## Major

| ID | Location | Problem | Fix |
|---|---|---|---|
| R5-1 | `async-tasks-blocking.md:112` (§C9, the `#[instrument]` bullet; 🔴 for secret leakage) | The bullet says `ret` "records only the `Ok` value for a `Result`". That holds only when `err` is also present. With `ret` alone the generated code is `let x = (move \|\| body)(); event!(return = ?x); x` (`tracing-attributes/src/expand.rs`, the `(None, Some(ret_event))` branch, sync and async alike), so the whole return value is recorded: an `Err(e)` goes to the log through `E`'s `Debug`. The crate's own doc note ("`ret` will record returned values if and only if the function returns `Result::Ok`") says otherwise; the spec follows the note, not the code. An agent that keeps `#[instrument(skip_all, ret)]` on a function returning `Result<T, E>` with a secret-bearing `E`, or redacts only `E`'s `Display` because "`err` records `Err` via `Display`", ships the leak the bullet exists to stop. Read on branch `v0.1.x`, not run. The ledger's probe (`sources.md:194`) covered `skip_all, ret` and `skip_all, err`, not `ret` alone on an `Err`. | State both cases: with `err`, `ret` records the `Ok` value and `err` the `Err` value; with `ret` alone the whole `Result` is recorded through `Debug`, `Err` included. Require the redaction on `E`'s `Debug` as well, or `err` plus a redacted `Display`. Add the `ret`-alone-on-`Err` case to the required assertions, and record the probe as an artifact (R3-1). |
